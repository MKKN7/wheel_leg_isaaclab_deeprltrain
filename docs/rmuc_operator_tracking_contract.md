# RMUC轮腿步兵：操作手指令跟踪契约

用户2026-09-27明确：以稳定跟踪转弯为主，姿态由策略选择，同时检查载荷、侧滑和稳定余量；最终上RMUC轮腿步兵赛场，由人控制。该要求优先于先前强制解析内倾的解释。不是改成自主导航，也不是以硬编码roll目标代替转弯能力。

## 控制链与任务

操作手发运动指令 → 指令接口/单位和时序处理 → 25D观测构造与完整组合RL → 四腿位置与两轮力矩目标 → 执行器。LQR只独立对照/备用接管，不作RL内环；最终无任务级速度/pitch/yaw补偿。具体遥控协议、发包频率和实机状态估计接口尚未验证，不假定现有键盘工具就是实车遥控链。

用户原定速度/双向转弯/起停/倒退/连续随机命令/动态切换/自转范围不减。要验收操作手持续变化的指令，不能只用每回合固定命令；需测试加减速、换向、左右连续切换、放杆归零、模式切换与失联/急停接管。命令整形参数应明确记录，不以悄悄降低操作手命令实现通过。未确认侧向平移输入，不擅自扩展操作手自由度。

## 姿态及验收

默认command_require_analytic_bank=False：关闭解析bank跟踪奖励/误差惩罚、active/retention bank硬门槛和按bank误差分配训练方向。保留姿态诊断、倾倒安全限制与一般姿态正则；“姿态自主”不等于不限制摔倒或危险姿态。历史复现可显式打开该开关。独立评估默认operator_tracking_v1；历史严格角度模式用--require-analytic-bank。角度数值继续输出，历史passed不改写。

速度/yaw/生存/高度/接触原门槛保持。新增控制步极值诊断包含全程及稳态的最小载荷比例、侧速/局部滚动误差最大值、准静态支撑proxy最小值，以及低载荷/接触不足/滑移事件比例和最长连续时间。事件阈值只是观测分类，尚不是经验证的实机安全门槛；不会拿本轮测得的最大值反推通过阈值。

正常转弯不要求左右载荷相等，也不要求法向合力正好沿机体上轴。net_forces只有法向，不能用来认证摩擦利用率。准静态proxy不是完整ZMP或角动量模型。控制步8ms采样可能漏掉子步短事件；最终还需动态扰动和实机目标动力验证。
