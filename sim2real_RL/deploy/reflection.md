## 4. 已找到的策略端事实：不能全推给硬件

### 4.1 v8 的“31项通过”并不代表向内压弯正确

[formal_acceptance_report.json](../../artifacts/h723_distill_v8/formal_acceptance_report.json) 记录同契约 Isaac 每点至少32回合、31/31教师技能保留；同时明确 `promoted=false`。更关键的是 formal_a/b 均为 `analytic_bank_required=false`，对应运行配置 `command_require_analytic_bank=false`。

当前验收源码 [evaluate_rmuc_grid.py](../../scripts/evaluate_rmuc_grid.py) 的 bank check 在未要求 analytic bank 时直接放行；[bank_geometry.py](../../source/agent_tasks/agent_tasks/direct/rmuc_wheel_leg/bank_geometry.py) 明确以“向航向左侧倾”为正，并用 `atan2(vx*yaw, 9.81)` 作准静态参考。原始报告如下：

|vx / yaw|平均有符号倾角|bank平均绝对误差|原报告|
|---|---:|---:|---|
|1.0 / +0.8|−5.044°|9.706°|passed=true，bank check=true|
|1.0 / +1.4|−7.037°|15.159°|passed=true，bank check=true|
|1.0 / −0.8|+1.547°|6.209°|passed=true，bank check=true|
|1.0 / −1.4|+4.874°|12.996°|passed=true，bank check=true|

这说明 **v8 在仿真中就有平均向弯外倾的行为**，不是必须假设实机接线错误才能解释。它不证明现场每一帧的原因，但足以否定“符号一定错、策略没有责任”。原始数值见 [formal_a](../../artifacts/h723_distill_v8/formal_a/evaluation.json)、[formal_b](../../artifacts/h723_distill_v8/formal_b/evaluation.json)。

后续应将 tracking、存活、正确倾向、双轮载荷/支撑余量分开验收；转弯瞬态允许合理反向预动作，不能要求每帧都符合准静态倾角。`atan(v*yaw/g)`也不是多接触轮腿机构所有姿态的唯一精确平衡角，应配实际加速度、COM、接触力判断。不能简单强开一个惩罚就宣布修好。

### 4.3 DR有启用，但远非“全部鲁棒性已覆盖”

正式报告为 DR strength=.1。最终采样读回（formal_a）为 Dfb约[.049003,.050976]、机械b约[.001901,.002300]、C约[.000954,.001399]；不是配置最大范围 [.04,.06]/[.001,.005]/[.0005,.005] 全部暴露。

传感器配置已启用；当时 delay_min=max=1，观测延迟概率.05、动作通信延迟概率.02，报告最大已暴露1周期。不能写成已覆盖每次1–3周期、实机任意推理抖动或长时间丢包。质量及独立惯量形状倍率读回约±2%，不是±20%；leg DR在该验收读回为false。

腿/轮 armature、响应和质量须按该版本实际读回核对，不能仅因文本提出就认定“没建模”。同样，资产质量有数值不代表带电池、云台、线缆的实机COM已对齐。

### 4.4 蒸馏还应保留反馈特性和恢复边界

v8 导出报告的PC数值对拍误差约1.52e−6，且31项Isaac技能保留，故不能笼统断言“小网络推理错了/容量必然不够”。但这不覆盖板端输入构造、CubeAI数值、未采到的切换/失稳边界和跨引擎闭环。

v8 augmentation_report明确548,864条是**局部合成扰动重标注**，不是额外真实闭环rollout，更不是最高DR覆盖。后续重点应是学生自主rollout偏离区、起停/切换、零速附近、真实传感器误差附近采样，再由经过该工况验证的冻结教师标注；不能用失败教师无条件纠正学生。训练/验证按轨迹和seed分开，避免相邻帧泄漏。

## 5. 轮阻尼补偿：该做，但要按v8实际契约做

v8 训练名义模型（两轮模型关节坐标；前进轮速为负）为：

```text
tau_motor_train = clip(-5.5*clip(a,-1,1) - 0.05*dq_joint, -5.5, 5.5)
tau_wheel_train = tau_motor_train - 0.002*dq_joint - 0.001*tanh(dq_joint/0.1)
```

既有部署参考的近似补偿路线为：

```text
tau_motor_real = clip(-5.5*clip(a,-1,1) - D_comp*dq_joint, -5.5, 5.5)
D_comp = 0.052  # v8交付参考值；必须显式填入，不是宏自动启用
```

若采用前进为正的轮坐标，统一换成 `omega_forward=-dq_joint`、`tau_forward=-tau_motor_joint` 后才可写 `clip(5.5*a-D_comp*omega_forward,±5.5)`。补偿使用观测同源、同符号的**未缩放输出轴rad/s轮速**；不能直接拿 `.05*dq` 的obs15/18作omega，也不能拿转子RPM直接代入。

当前缺少补偿意味着缺少约.05量级主动速度反馈，明显偏离v8训练闭环，优先级高。补偿在正确定义下是耗散项，但：

1. 不是单独给实机“加一个被动D”；它占电磁电流预算，必须在±5.5内部，物理b/C不能重复写成部署电流。
2. `.052 + b_real` 不等于 `.05 + .002` 的精确实现。若b_real在.001–.005，实机非饱和总斜率约.053–.057，训练该档约.0509–.0533；**当前窄DR不保证覆盖上端**。饱和区内外限幅位置还有差异。对拍和补偿A/B必须记录D_comp，不能笼统称“DR已兜住”。
3. D_comp=.05更直接对应训练主动通道，.052属于已有近似补偿选择；本次不擅自替换交付参数，也不把任何一个未测值宣布为最终值。后续用确认的机械先验/读回决定同契约小幅对照。
4. omega=0时阻尼力矩为0，它不能抵消静态偏置、提供位置保持或修正错误速度估计。不能保证补上D后不溜车、不顿挫。
5. 1ms轮执行与2ms训练不自动等价；必须包含相同滤波、保持和反馈采样。高采样频率不弥补错误的信号延迟。
6. 3Nm是持续热/负载参考，不可把瞬态峰值改成3Nm。校核Iq、实际电流上限、温度、反电动势/电压饱和；不能只检查浮点力矩变量。

`rmuc_low_level.c` 已有补偿单施加点，但初始化允许D=0，且没有替集成方自动配置.052。存在这个文件不能证明板上启用了补偿。旧控制器不同电流系数/限流代码也不能未经检查移植。实机缺项应先恢复契约，再判断余下需要RL适应的残差，不能让DR替代正确映射。

### 10.1 可尝试的分轮补偿，不是已批准的部署参数

以下计算仅在数据为轮轴SI量、摩擦模型对应、力矩/电流增益和符号正确的前提下成立。当前教师阶段 `D_fb=.05、b_sim=.002、C_sim=.001`，对应未饱和总黏性系数`.052`；旧v8实际部署必须先核对v8自己的checkpoint/consumer契约，不能直接套用最新教师参数。

```text
tau_drive = 5.5 * clip(action, -1, 1)  # 已统一为物理轮轴坐标
D_comp_i = .052 - B_hat_i
delta_C_i = Tc_hat_i - .001
tau_motor = clip(tau_drive - D_comp_i * omega
                 + delta_C_i * friction_direction(omega), -5.5, 5.5)
```

候选计算：左/右 `D_comp=.0494515/.05133043 N·m·s/rad`；左/右额外库仑前馈`.053699/.051843 N·m`。库仑前馈沿运动方向抵消多余损耗，主动阻尼阻碍运动，二者均占电磁预算并在±5.5限幅内。物理机械摩擦由实机自然产生，部署代码不能再扣一遍。3N·m仍只作持续热/负载参考。

`friction_direction`不能未经验证直接采用跨零硬sign；近零速需平滑、限幅，并验证噪声、起步、反向和零命令漂移。平滑尺度/静摩擦与运动摩擦差别尚未辨识，不能照抄任意omega_eps。观测缩放后的数值不能直接当物理rad/s使用，左右符号只转换一次。现阶段未据此修改controller或训练参数。

### 10.2 补偿律不能保证参数变化后的鲁棒性

若补偿采用固定估计值 `B_hat、Tc_hat`，在未饱和、即时同源测量且摩擦函数相同的简化条件下：

```text
B_effective = .052 + (B_real - B_hat)
C_effective = .001 + (Tc_real - Tc_hat)
```

因此固定补偿消除的是名义差异，温度、载荷、装配等导致的变化仍以残差进入动力学。过补库仑摩擦可能使剩余摩擦在某些速度区域变为助推，造成爬行/抖动；不能因为黏性补偿量接近旧先验，就宣称新的库仑差异无影响。上式不是含延迟、近零速静摩擦或电磁饱和时的精确等效。

纯延迟不能用静态力矩补偿消除。给快轮额外增加4ms只可能对齐左右时序，不能消除共同滞后，也可能影响平衡；不得未经对照直接启用。轮端1kHz执行同样不能证明测量或执行延迟已解决。

### 10.3 最小验证路线与放行证据

1. 确认输出轴单位、力矩/电流增益、符号、辨识期间其他控制项及原始时间戳；保留左右独立参数和估计不确定范围。
2. 先在验证模型中使用真实左右B/Tc/延迟及**实际部署补偿律**，冻结同一待部署checkpoint测试；不必立即重训，但不能完全不改验证模型。
3. 测试补偿估计误差、冷/热与供电变化、左右不对称、实际测量/通信/执行延迟、反转饱和；参数范围由数据/重复试验确定，不能凭空假定原DR已覆盖。仿真机械损耗置于电磁限幅外，补偿置于限幅内，避免重复或漏施加。
4. 关键工况包括零命令、低速正反向、起停/换向、直行和慢转组合、自转进入/退出；同步检查速度、腿摆角、姿态、滑移、擦地、饱和比例、电流和温度。腿对齐惩罚只用于直行/待机，不强迫转弯对称。
5. 通过冻结策略测试后再做受控实机对照；不通过则针对补偿后的残差和延迟续训，保留旧技能retention。参数静态对拍、名义点成功或平均指标通过都不能替代多seed/逐副本与动态工况验收。

**当前结论：补偿路线可作为减少重训工作量的候选方案；参数变化后的鲁棒性未验证，不能保证高sim2real成功率。** 本节只记录辨识与验证要求，不改变训练命令接口或部署策略。
